# ネットワークの概念

**日本語**（このページ）| [English](network-concept.en.md)  
**参照:** [Phase 1 設計](phase1-design.md)、[データ同期設計](sync-db-plan.md)、[データ同期コンセプト](data-sync-concept.md)

---

## 1. 概要

- **ネットワーク** = メンバー（DID）の集合。**最低 1 人**（個人データ空間として利用可能）。
- **1 対 1** は「2 人ネットワーク」のケースとして扱う。1 対 1 専用の概念は持たない。
- ネットワークのメンバーリスト・ロール情報は各ノードがローカルに保持する（DHT 上にネットワーク実体は持たない）。
- **権限管理**はロール DAG（有向非巡回グラフ）で行う。アプリがロール定義を提供し、LinkSelf がロールに基づくアクセス制御を実行する。

---

## 2. ネットワーク情報の保持

- ネットワーク情報（メンバー DID リスト、ロール割り当て）はインターフェース化された `network.Store` で管理する。
- デフォルト実装はインメモリ（`MemStore`）と SQLite3。
- 各デバイスのローカルに保持し、中央サーバーや DHT にはネットワーク実体を置かない。

---

## 3. メンバーと脱退

| 項目 | 内容 |
|------|------|
| **メンバー** | ネットワークに属する DID のリスト。1 人以上。 |
| **脱退** | メンバーはいつでもネットワークを脱退できる。 |
| **1 人ネットワーク** | メンバーが 1 人の場合は個人データ空間として機能する。 |
| **2 人ネットワーク** | メンバーが 2 人のとき、片方が脱退するとそのネットワークは 1 人ネットワークになる。 |

---

## 4. ロール DAG（権限管理）

オーナー概念は**ロール DAG に統合**されている。ネットワーク管理操作（メンバー追加・キック・ロール変更）の権限はスイートのロール定義で決まる。

### ロール定義

アプリが `Config.Roles` でロール階層を定義する:

```go
Roles: role.RoleDefs{
    "viewer":     {},                              // 基本ロール
    "nurse":      {Includes: []string{"viewer"}},  // viewer の権限を含む
    "admin":      {Includes: []string{"nurse"}},   // nurse の権限を含む
}
```

ロールの関係は有向非巡回グラフ（DAG）であり、`Includes` で包含関係を定義する。循環参照はエラー。

### 管理操作の権限

| 操作 | 必要なロール |
|------|------------|
| メンバー追加 | `Config.AdminRole`（デフォルト: "admin"） |
| メンバーキック | `Config.AdminRole` |
| ロール割り当て変更 | `Config.AdminRole` |
| 脱退 | 誰でも（自分自身） |

### メンバーへのロール割り当て

- 1 メンバー = 1 ロール。複数ロールの兼任は DAG で複合ロールを定義して対応する。
- ロール未割り当てのメンバーは最低限の権限（`members` 権限のみ）を持つ。

---

## 5. テーブル権限と同期スコープ

テーブル単位の権限設定がデータの同期範囲を決定する:

| read 権限 | 同期範囲 |
|-----------|---------|
| `self` | 同一ユーザーのデバイス間のみ |
| `<role_name>` | 該当ロール以上のメンバーにのみ配信 |
| `members` | ネットワークメンバー全員に配信 |

詳細は [データ同期コンセプト §6](data-sync-concept.md) を参照。

---

## 6. 権限はアプリ層が定義する

- ロール定義はアプリがハードコードする。LinkSelf は「ロールとは何か」を知らない。
- テーブル単位の read/write/delete 権限は `MyDB.SetPermissions()` で設定する。
- 行レベルのアクセス制御は LinkSelf では提供しない。アプリが WHERE 句で制御する。

## 8. 実装

- **実装**: `core/internal/network`。ストアはインターフェース（`Store`）で定義し、インメモリ実装（`MemStore`）と SQLite 実装を同梱。
- **ドメインロジック**: `Service`（`Create`, `AddMember`, `Leave`, `Kick`, `SetMemberRole`）。全管理操作で `AdminRole` のロール DAG 権限チェックを実行。
- **旧実装**: `core/internal/group` はオーナーベースの旧実装。`core/internal/network` が後継。
- **テスト**: ストア単体、サービス単体（ロール権限チェック含む）。
